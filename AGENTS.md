## Mandatory factory-first execution

For every coding, testing, debugging, research or review task, optimize **verified progress per unit of paid agent usage**. The primary Codex/ChatGPT worker coordinates; it is not the default machine for repetitive work.

Before substantial work, read this repository's authority and the owner's installed `factory-first` skill/runbook. Inspect current factory health, available worker/runner capabilities, active jobs/leases and relevant existing receipts. Create a short routing plan. Do not assume a listed pool is healthy, licensed, qualified or idle.

- Dispatch independent repository searches, log summaries, lint/type checks, unit/integration tests, builds, browser screenshots and acceptance checks to the appropriate existing factory pools or repository-authorized self-hosted runners. Use dependency-ready parallel jobs, bounded resources and isolated workspaces; one integration owner, no overlapping writers.
- Send narrowly scoped small coding/documentation tasks to a **currently qualified** lower-cost/local worker when it reduces total expected cost. Keep architecture, ambiguous debugging, security/authorization, money/state integrity, integration and release decisions with the primary worker. Do not invent a coding pool from idle test runners.
- Reuse a result only when source/input hashes, toolchain/environment, command and acceptance scope match. Never reuse stale live/provider/UI evidence as current proof. Do not duplicate an active job or rerun an unchanged full suite merely to fill capacity.
- Submit bounded jobs, continue other ready work, then consume compact result receipts and failing excerpts. Avoid second-by-second polling, streaming full logs into model context, recursive agent spawning, and repeated checkpoint-only conversations.
- Preserve project quality and safety gates. Review actual rendered output for UI work. Independently verify code changes and exact release artifacts. Missing, failed, stale or unperformed evidence is not PASS.
- No new subscriptions, overages, paid fallback, quota bypass or production/trading authority changes are implied. Honor the project's stronger restrictions and the owner's current budgets. Factory unavailable: record the observed blocker and use a bounded, documented fallback; never silently turn off safety gates.

A trivial, targeted probe may run inline when it is faster and cheaper than dispatch; document the exception. Full suites/builds and repeated mechanical work are factory-first. Maximum efficiency means useful accepted work within admission limits, **not 100% CPU utilization**.

At handoff record the chosen routes, job/run IDs, cache reuse, exact tested revision, remaining blockers and any routing exception. On new repository creation, install this contract before starting substantive work.
